# SportIQ — AI Sports Analysis Platform

**Live App:** https://sport-iq-git-main-shwetas-projects-fd91a33a.vercel.app/
**API:** https://sportiq-voxv.onrender.com
**API Docs:** https://sportiq-voxv.onrender.com/api-docs

An AI-powered sports analysis platform for Football, Cricket, and Tennis. Built to demonstrate a production RAG pipeline with real data ingestion, intent-driven retrieval, and dual analyst generation.

---

## Features

- **Dual AI Analysts** — Two Claude-powered personas debate any sports question simultaneously via SSE streaming. The Tactician reasons from technique and style. The Statistician reasons from data and numbers. Each gets its own separate retrieval pipeline — they never share context.
- **Player Profile** — Real-time factual data (age, nationality, position, team) from TheSportsDB. Career summary and achievements generated by Claude grounded in RAG context.
- **Head to Head** — Side-by-side player comparison. Football ratings calculated from real per-90 stats (API-Football) using position-weighted formulas — not Claude's opinion.
- **Career Timeline** — Key career milestones generated per player.
- **Search History** — Saved per user via Supabase auth (email + Google OAuth).

## RAG Architecture

### Smart RAG — not Naive RAG

Before retrieving anything, the question is classified by intent using Claude Haiku:

| Intent | Retrieval |
|---|---|
| `opinion` | Skipped — Claude reasons from its own knowledge |
| `player_stats` | Stats documents only |
| `player_technique` | Narrative documents only |
| `comparison` / `general` | Both document types in parallel |

A similarity threshold of **0.65** gates quality — documents below threshold are discarded and Claude is told explicitly that no context was found rather than receiving empty or weak documents.

### Retrieval Pipeline

```
Question
   ↓
Intent Classification (Claude Haiku)
   ↓
Voyage AI Embedding (voyage-large-2)
   ↓
Supabase pgvector similarity search
   ↓
Threshold filter (≥ 0.65)
   ↓
Two isolated context prompts — one per analyst
   ↓
Dual Claude Sonnet streams via SSE
```

### Dual Isolated Pipelines

The Tactician and The Statistician each retrieve from their own document type:

- **`narrative` docs** → technique, playing style, tactical analysis → The Tactician
- **`stats` docs** → career numbers, records, tournament data → The Statistician

They cannot cross-contaminate each other's context.

## Knowledge Base — What's Ingested

The knowledge base (`sports_docs` table in Supabase) has three layers:

### Layer 1 — Hand-curated Player Docs
Tactical analysis documents written specifically for this platform covering top players across all three sports. Includes specific technique breakdowns, positional tendencies, and statistical profiles not available in this form elsewhere.

**Football:** Messi, Ronaldo, Haaland, De Bruyne, Mbappé
**Cricket:** Bumrah, Kohli, Dhoni, Tendulkar
**Tennis:** Federer, Nadal, Djokovic, Sinner

### Layer 2 — Live RSS Scraper
A scraper pulls fresh match reports and news articles from:

| Feed | Sport |
|---|---|
| BBC Sport Football | football |
| Sky Sports | football |
| BBC Sport Cricket | cricket |
| ESPN Cricinfo | cricket |
| BBC Sport Tennis | tennis |

Articles are chunked into ~150 word paragraphs before embedding — each chunk is embedded and stored separately so retrieval returns the specific relevant paragraph, not the whole article. Document type (`narrative` or `stats`) is auto-detected from content.

Trigger a scrape: `POST /api/scrape`

### Layer 2b — Fictional Players (RAG Pipeline Verification)
Three completely fictional players with invented stats and incidents — ingested specifically to prove the RAG pipeline is working end-to-end.

| Player | Sport | Key Invented Fact |
|---|---|---|
| **Devraj Nambiar** | Cricket | 214* in Cape Town after India were 34/4. 847 runs in England series — fictional record. Weakness against left-arm pace documented. |
| **Lucas Ferreira** | Football | Scored "O Giro" in Copa America final 89th min to equalise. 18 assists in La Liga 2024-25 — fictional record. |
| **Mika Virtanen** | Tennis | Won Wimbledon 2025. Saved 4 match points vs Djokovic in the semi-final. First Finnish player to win a Grand Slam. |

**Why fictional players?** Claude has zero training data on these players. If the Dual Analyst cites "O Giro" or "847 runs in the England series" — those facts can only have come from the knowledge base. This makes it a clean, unambiguous proof that the retrieval pipeline is working rather than Claude answering from training data.

### Layer 3 — Auto-ingest on Player Lookup
When a player profile is looked up via `/api/player`, their TheSportsDB data is automatically ingested into the knowledge base in the background if not already present.

## Testing

Tests live in a separate repo and hit the deployed API directly — intentional separation so RAG quality can be evaluated independently of the app deployment cycle.

Evaluation stack:
- **RAGAS** — retrieval quality (context precision, recall, groundedness)
- **DeepEval** — generation quality (answer relevancy, faithfulness, persona fidelity)
- **Gemini Flash** — judge model (independent from Claude to avoid evaluation bias)
